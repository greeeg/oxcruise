# Rules and categories

A rule checks the module graph and reports violations. Each built-in rule is in one category.
A category switches all its rules on or off together.

## Categories

| Category | Contains | Default level |
|---|---|---|
| `correctness` | Rules that find code that is almost certainly wrong. | `error` |
| `suspicious` | Rules that find code that is probably wrong or useless. | `warn` |
| `style` | Rules about code style. | `off` |
| `restriction` | Rules that forbid a feature or a pattern. They are opt-in. | `off` |
| `nursery` | New rules. Their behavior can still change. | `off` |

Use the `categories` key to change the level of a category:

```ts
export default defineConfig({
  categories: { correctness: "error", suspicious: "error", restriction: "warn" },
});
```

## Levels

A level is `off`, `warn` or `error`.

* `off` disables the rule.
* `warn` reports a violation as a warning. A warning does not change the exit code, unless you use `--deny-warnings` or `--max-warnings`.
* `error` reports a violation as an error. An error gives exit code `1`.

## Configure one rule

A rule in the `rules` key wins over its category. A rule that its category switches off can still be on here.
Give a level, or give an object with a `level` and the options of the rule.
An object without `level` means `error`.

```ts
export default defineConfig({
  rules: {
    "orphan-modules": "error",
    "circular-dependencies": { level: "error", ignore: ["src/index.ts"] },
    "peer-dependencies": "warn",
  },
});
```

In `overrides`, an object without `level` keeps the level that the rule has for those modules and replaces the options.
Oxcruise reserves the name `level`. No rule has an option with this name.

Oxcruise checks the options of every rule. It stops with the name of the rule and the option when an option is not valid.

## List the rules

Run `npx oxcruise --rules` to list the built-in rules by category. Add `-f json` for JSON.
The [rules reference](/reference/rules) has one page for each rule.

## Other kinds of rules

* [`forbid`](/reference/config#forbid) holds your own rules for dependencies that the project does not allow.
* [`layers`](/reference/rules/layers) and [`visibility`](/reference/rules/visibility) are two built-in rules for architecture.
* [`folder-structure`](/reference/rules/folder-structure) is a built-in rule for the shape of the file tree.
* A [JS plugin](/features/js-plugins) can add rules that you write in TypeScript.

## Cycles and suppression

Oxcruise reports a cycle once, and not once for each dependency in it. A cycle counts as suppressed when one of its dependencies has an [ignore comment](/features/ignore#ignore-violations).
