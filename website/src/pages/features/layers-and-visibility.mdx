# Layers and internal modules

Two built-in rules in the `restriction` category check the structure of a project.
They are off by default. Enable them in `rules`.

## Layers

The [`layers`](/reference/rules/layers) rule enforces a layered architecture.
Name each layer and give its globs. Then list the layers that each layer can import.

```ts
export default defineConfig({
  rules: {
    layers: [
      "error",
      {
        layers: { ui: "src/ui/**", domain: "src/domain/**", db: "src/db/**" },
        allow: { ui: ["domain"], domain: ["db"], db: [] },
      },
    ],
  },
});
```

* A module can always import a module in its own layer.
* A layer that `allow` does not list has no limit.
* When layers overlap, the first layer by name wins.

With this config, a module in `src/ui/` cannot import `src/db/`.

## Internal modules

The [`internal-modules`](/reference/rules/internal-modules) rule works like the `internal` directories of the Go language.
Only code under `a/b/` can import a module under `a/b/internal/`.

```ts
export default defineConfig({
  rules: { "internal-modules": "error" },
});
```

To use another directory name, set the `marker` option:

```ts
export default defineConfig({
  rules: { "internal-modules": ["error", { marker: "private" }] },
});
```

## When to use a forbid rule

Use `layers` when you have an ordered set of layers. Use [`forbid`](/features/forbid-rules) for a single restriction or for captures.
