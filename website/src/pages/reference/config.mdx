# Configuration reference

The oxcruise config file.
Oxcruise reads `oxcruise.config.ts` or `.oxcruiserc.json`. See [Configuration](/guide/configuration) for a guide.
The config rejects keys that this page does not list.
A key of type `string` or a list takes globs. A leading `!` negates a glob: `["src/**", "!src/**/*.test.ts"]`.

## $schema

Type: `string`.

The URL or path of the JSON schema, for editors.

## calls

Type: list of `string`.

Names of functions whose first string argument is a dependency, for example `jest.mock`.

## categories

Type: object of [`Level`](#level), by name.

The level of each category of built-in rules. The categories are `correctness`, `suspicious`, `style`, `restriction` and `nursery`. The default is `correctness: error, suspicious: warn`.

## doNotFollow

Type: `string` or a list.

Globs of modules that stay in the graph. Oxcruise does not parse their imports.

## entries

Type: `string` or a list.

Files, directories or globs where the graph starts. The default is `["."]`.

## extends

Type: list of `string`.

Paths to other config files. Their settings are the base, and this file changes them.

## forbid

Type: list of [`ForbidRule`](#forbidrule).

Forbidden dependencies, written as rules.

## ignorePatterns

Type: `string` or a list.

Globs of modules to leave out of the graph. Oxcruise also uses the rules of `.gitignore` when it looks for modules.

## jsPlugins

Type: list of [`JsPlugin`](#jsplugin).

JS or TS plugins: paths or package names.

## overrides

Type: list of [`Override`](#override).

Settings that change rules for some modules.

## resolve

Type: [`ResolveSection`](#resolvesection).

How oxcruise resolves imports.

## rules

Type: object of [`RuleEntry`](#ruleentry), by name.

The built-in and plugin rules, by name. A rule listed here wins over its category.

## symbols

Type: `boolean`. Default: `false`.

Extract exports and the names that each import uses, for `json` output and plugins. Rules that need them enable this option.

## Types

The keys above refer to these types.

### AliasedPlugin

| Key | Type | Default | Description |
|---|---|---|---|
| `name` (required) | `string` |  | The prefix of the rules: `<name>/<rule>`. It replaces the `meta.name` of the plugin. |
| `specifier` (required) | `string` |  | A path or a package name. |

### ForbidRule

A dependency that the project does not allow. An import from a module that matches `from` to a target that matches `to` is a violation.

| Key | Type | Default | Description |
|---|---|---|---|
| `from` | `string` or a list |  | Globs of the importing module. `{name}` captures a path segment, and `to` can use the capture. |
| `message` | `string` |  | Why the dependency is forbidden. Oxcruise shows it instead of the generic message. |
| `name` (required) | `string` |  | The name of the rule. Reports and `overrides` use it. |
| `severity` | [`Level`](#level) | `"error"` | The level of the rule. |
| `to` | [`ToSpec`](#tospec) |  | The target of the dependency: globs, or an object with conditions. |

### JsPlugin

A JS or TS plugin: a path or package name, or an object that also gives the prefix of its rules.

One of:

* `string`: A path, such as `"./tools/acme.ts"`, or a package name, such as `"acme"`. For a package name, oxcruise tries `oxcruise-plugin-acme` first and then `acme`.
* [`AliasedPlugin`](#aliasedplugin): An object with the specifier of the plugin and the prefix of its rules.

### Level

The level of a rule. `off` disables the rule, `warn` reports violations as warnings, and `error` reports them as errors.

Allowed values: `"off"` or `"warn"` or `"error"`.

### ModuleKind

What a module is. The names are the ones the config (`to.kind`), the JSON and plugins use.

| Value | Description |
|---|---|
| `"local"` | A file of the project, parsed. |
| `"package"` | A file inside `node_modules`: resolved, not parsed. |
| `"builtin"` | A Node.js built-in module. |
| `"unresolved"` | An import that could not be resolved. |

### Override

Changes the settings of rules for some modules.

| Key | Type | Default | Description |
|---|---|---|---|
| `files` (required) | `string` or a list |  | Globs of the importing modules that this override applies to. |
| `rules` | object of [`RuleEntry`](#ruleentry), by name |  | The rules to change, by name. |

### Relation

How two modules relate, for the `relation` condition.

| Value | Description |
|---|---|
| `"same-folder"` | `to` is in the same folder as `from`. |
| `"descendant-of-from"` | `to` is below the folder of `from`. |
| `"descendant-of-from-parent"` | `to` is below the parent folder of `from`. |
| `"sibling"` | `to` is in a sibling folder of `from`'s folder. |
| `"same-package"` | `to` is in the same workspace package as `from`. |
| `"cross-package"` | `to` is in another workspace package than `from`. |

### ResolveSection

How oxcruise resolves imports.

| Key | Type | Default | Description |
|---|---|---|---|
| `alias` | object of `string` or a list, by name |  | Path aliases. For example `{ "~": "./src" }`. |
| `conditions` | list of `string` |  | Export and import condition names. Oxcruise tries them before `import`, `require`, `node` and `default`. For example, use `["source"]` to resolve workspace packages to their source. |
| `tsconfig` | `string` |  | The tsconfig for every file. By default, each file uses the nearest tsconfig. |

### RuleEntry

The setting of a rule: a level, or an array of a level and an options object. For example `"error"` or `["error", { "includeTypeOnly": true }]`.

One of:

* [`Level`](#level)
* `array`

### ToCondition

Conditions on the dependency and the module it points to.

| Key | Type | Default | Description |
|---|---|---|---|
| `dynamic` | `boolean` |  | The dependency is a dynamic `import()`. |
| `kind` | [`ModuleKind`](#modulekind) or a list |  | What the dependency points to. A dependency matches when it has any of these kinds. By default, every kind matches, except for `reachable` rules, which check only `local` and `package` modules. |
| `path` | `string` or a list |  | Globs that the target of the dependency must match. |
| `reachable` | `boolean` |  | `to` is reachable from `from` through other modules. |
| `relation` | [`Relation`](#relation) or a list |  | How `to` relates to `from`. A dependency matches when it has any of these relations. |
| `typeOnly` | `boolean` |  | The dependency is only `import type` or `export type`. |

### ToSpec

One of:

* `string` or a list: Globs the dependency's target must match.
* [`ToCondition`](#tocondition): An object with conditions on the dependency and its target.
